# O-3 스케줄러 기상 정확도

```sh
STATES=10000 DELAY_S=60 node tests/ops/scheduler-accuracy/run.mjs   # 실행 중 로컬 스택(워커 포함) 대상
```

기준(DEV-sub-03 O-3): delay 1분 × 1만 상태, 기상 오차 ±5s p99. 같은 `next_wake_at`을 가진 상태 N건을 넣고
완료 시각(`journey_states.updated_at`) − 기상 시각의 분포를 잰다. 발송은 크리덴셜이 없어 failed로 끝난다(측정과 무관).

## 2026-09-10 실측 (로컬 docker, 1만 상태)

| 워커 | p50 | p95 | p99 | max |
|---|---|---|---|---|
| 순차 실행(수정 전) | 21.97s | 30.74s | **31.75s** | 31.83s |
| 틱 내 16 병렬 + 배치 가득 차면 즉시 재클레임 | 1.45s | 2.40s | **2.48s** | 2.49s |

수정 전 처리율은 ≈310 상태/s(배치 500을 단일 고루틴이 순차 실행, 1초 틱), 수정 후 ≈4,000 상태/s.
병렬 실행 뒤 M-4 카오스(3,000명·kill -9 ×5)를 다시 돌려 중복 0·이중 로그 0을 확인했다.

## 경계

- 같은 호스트 docker 워커 1개. 노드 실행이 CH 조건 평가를 포함하면 건당 비용이 커진다(이 측정은 message 노드).
- 병렬도(`tickConcurrency=16`)와 PG 풀(32)은 상수다. 다중 인스턴스 배치에서는 인스턴스 수만큼 곱해진다.
