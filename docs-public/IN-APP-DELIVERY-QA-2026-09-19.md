# 콘텐츠 검수 전송 안정화 — 2026-09-19 KST

SDK 0.2.5는 검수 기록을 보호 저장소에 먼저 저장하고, 같은 event ID로 순서대로 전송한다. End는 전송 후 세션을 종료하며 실패 기록을 삭제하지 않는다. 전송 상태는 대기·전송 중·서버 확인·실패를 구분하고 예제 앱에 재시도·명시적 폐기를 제공한다. 서버 확인은 수신 확인이며 검수 승인이 아니다.

## 검증 범위

- Swift: 신규 전송 테스트 7개, 기존 인앱 테스트와 전체 Swift 테스트 통과.
- Android: 신규 전송 테스트 8개, 인앱 전체 18개 통과. SDK 샘플 앱 빌드 통과.
- 두 플랫폼 단위 테스트: 응답 유실 후 동일 ID 재시도, 오프라인 종료 후 재시작, 저장 실패, 전송 중 종료/폐기, 영구 거절 시 성공 표시 금지, 중단된 실행의 실패 기록 복구.
- iPhone 16 Pro / iOS 18.1 Simulator: 응답 유실, 오프라인 프로세스 재실행, 백그라운드 복귀를 실제 WebView와 로컬 HTTP 장애 주입 서버로 검증. 암호화 저장은 실제 Keychain 사용.
- Android emulator: 동일 세 경로를 실제 WebView와 Keystore 저장소로 검증. 재실행 시 과거 광고가 다시 열리지 않는지 확인.
- 장애 주입 서버 대사: 최초 완료 시점의 전송 시도 92회, 고유 기록 52건, 미수신 ID 0. 응답을 유실한 dismiss는 같은 ID로 2회 요청되고 1건만 저장됨. UI 자동화 재시행도 포함한 누적 수치다.
- 실제 PostgreSQL: 격리된 테스트 스키마에서 워크벤치 통합 테스트 3개 통과. 완료 후 같은 dismiss event ID 동시 재요청 2건은 수신 성공하고 DB에는 1건만 유지. 다른 payload로 같은 ID 재사용 시 409.
- 웹: 한·영 개발자센터/사용 가이드, 테마, 390px 모바일, 전체 Swift/Kotlin 코드 복사 일치, 브라우저 오류 없음 확인.

초기 시뮬레이터 unsigned 빌드는 Keychain 접근 실패를 표시했다. 시뮬레이터 전용 entitlement와 ad-hoc 서명으로 수정하여 재검증했다. Android 자동화에서는 UIAutomator 종료 및 복귀 시 키보드가 상태를 가리는 문제가 있어 자동화 재시도와 키보드 정리를 적용했다. 이 초기 실행은 통과 수치에 포함하지 않는다.

## 보장 범위와 제한

- 테스트 코드 자체는 저장하지 않고, 전송용 단기 자격과 대기 기록만 iOS Keychain / Android Keystore AES-GCM 저장소에 보관한다. API URL·SDK 키마다 하나의 클라이언트만 소유한다.
- 재시작 시 클라이언트를 생성해야 전송만 복구된다. 명령·광고는 복구하지 않는다. 백그라운드 전송 지속 실행을 보장하지 않는다.
- 테스트 자격 30분, 활성 실행 5분의 서버 유효기간은 연장되지 않는다. 만료·폐기·취소된 검수의 기록은 영구 거절될 수 있으며 실패로 남는다. 이후 명시적으로 폐기하고 새 검수가 필요하다.
- 저장 실패 전 이벤트, 명시적 폐기, 앱 삭제는 수신 보장 범위 밖이다. 앱 재실행만으로 이미 만료된 서버 검수를 되살리지 않는다.
- 이 검증은 시뮬레이터/에뮬레이터와 로컬 서버 기준이다. 실제 iPhone/Android 단말 푸시, 원격 운영 콘솔의 검수 승인, 24시간 연속 운영 시험을 수행했다는 의미가 아니다.
