# 인앱 SDK 0.2.1 실기기 검증 — 2026-09-17

대상은 NudgeOn iOS SPM / Android Maven Central 0.2.1과 Godspell/Worshiplog 1.2637.0이다. iPhone 15 Pro(iOS 27.0), Galaxy Z Fold3 SM-F926N(Android 15)에서 확인했다. 운영 배포 승인을 의미하지 않으며, 격리된 QA 캠페인·서버를 사용했다.

Android는 기존 앱과 서명이 달라 `com.ethan.worshiplog.nudgeonqa` 별도 Debug 앱을 설치했다. 기존 앱과 데이터는 보존했다. QA 복사본은 Firebase 설정 파일을 제외했다. iOS는 개발 서명으로 기존 앱을 갱신하고 데이터를 유지했다.

## 기본 흐름

양쪽 실기기에서 투명 HTML 팝업 표시, `impression`, 사용자가 직접 누른 ‘오늘 하루 안 보기’의 `hide_today` 및 `dismiss(hide_today)`를 확인했다. 60초 노출 간격이 지난 후 앱을 완전히 종료·재실행해도 같은 캠페인이 다시 표시되지 않았다. 숨김 기준은 다음 UTC 자정으로, 한국 시간 오전 9시다. Android에서는 이벤트 버튼의 콘티 화면 이동과 `action(join_event)`도 확인했다.

기존 단위 테스트는 iOS 실기기 11개, Android 로컬 20개가 통과했다. Android 실기기 UI 검증과 로컬 단위 테스트를 구분한다.

연결 단절은 단말 전체의 Wi-Fi/통신망을 끄는 대신 NudgeOn 전용 프록시에서 소켓 연결을 끊어 재현했다. 응답 유실은 서버가 이벤트를 저장한 뒤 HTTP 성공 응답만 차단했다. 비행기 모드·실제 이동통신 전환까지 검증한 것은 아니다.

백그라운드 및 캠페인 중지 시의 `CONTEXT_CHANGED`는 당시 SDK 0.2.1의 의도된 정리 경로다. 캠페인 중지는 서버 상태를 `cancelled`로 유지하고 늦게 도착한 실패 이벤트가 다시 활성화하지 않았다.

## 0.2.1에서 발견한 개선 항목 (아래 0.2.2에서 해결)

- **EX-01 — HTML 예제의 낮은 화면 높이 대응:** Fold3 펼친 가로 화면에서 카드 하단의 둥근 모서리와 바깥 여백이 화면 아래로 잘린다. CTA·숨김·닫기 버튼과 네이티브 닫기는 접근 가능했다. 낮은 높이에서 아트·여백을 줄이거나 카드 내부 스크롤을 명시하는 개선 및 재검증이 필요하다. 이번 테스트에서는 예제/SDK 소스를 수정하지 않았다.
- **EX-02 — 정리 사유 세분화:** 정상적인 백그라운드 전환과 운영자 중지도 `failed(CONTEXT_CHANGED)`로 표시된다. 실제 장애와 구분해서 볼 수 있도록 진단/리포트 사유를 세분화하면 좋다. 이벤트 유실이나 중복으로 관찰된 문제는 아니다.

## 증거와 범위

로컬 검증 산출물은 `~/Downloads/NudgeOn-Exceptions-2026-09-17/`에 보관했다. 화면 캡처, 단절/복구 전후 서버 스냅샷, 인증 정보를 제외한 로컬 큐 스냅샷, 프록시 장애 주입 기록을 포함한다. 기본 흐름 결과는 `~/Downloads/NudgeOn-iPhone-2026-09-17/`, `~/Downloads/NudgeOn-Android-2026-09-17/`에 있다.

종료 후 양쪽 테스트 앱의 익명 사용 분석을 OFF로 돌리고, Android 화면 회전 설정을 테스트 전 값으로 복구했다. 임시 API·프록시·HTTPS 터널·ADB reverse와 격리된 QA DB 스키마는 정리했다. 설치된 Debug 앱으로 캠페인을 다시 확인하려면 테스트 서버 연결이 필요하다.

운영 HTTPS 콘텐츠 호스트·스토어 Release 빌드·APNs/FCM 발송·장시간 단절·OS에 의한 프로세스 종료·iOS 가로 UI·다양한 OS/WebView 버전 전체를 이번 결과로 완료 처리하지 않는다. Godspell iOS의 일반 화면은 세로 고정이다.
