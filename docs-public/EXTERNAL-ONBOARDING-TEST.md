# 외부 개발자 온보딩 검증 — 실행 전 기록지

B-3는 외부 개발자 **3명**이 문서만 보고 30분 안에 첫 실제 푸시를 확인하는
시험이다. 내부 자동 시험·모의 콜백·팀원의 대신 설치로 완료 처리하지 않는다.
현재 세 참가자 기록은 모두 **미실행**이다. 이번 8시간 작업은 단말 푸시를
제외했으므로 이 문서는 다음 검증을 위한 준비물이다.

## 제공할 자료

- [설치·로그인 안내](DEPLOY.md), [콘솔 화면 안내](CONSOLE-GUIDE.md)
- [첫 실기기 푸시](FIRST-REAL-PUSH.md), [SDK·베타 현재 상태](RELEASE-CHECKLIST.md)
- 실행할 플랫폼과 공개 SDK 버전. 현재 공개 native는 0.2.5다. [최신 연결 안내](APP-LAUNCH-ADS.md)를 확인한다. RN/Flutter 0.1.3은
  로그인 후 게시 예정이므로 공개 배포 완료로 소개하지 않는다.
- 권한이 있는 시험용 서버·APNs/FCM 프로젝트·앱 서명·시험 기기. 고객 데이터와
  기존 운영 앱을 대신 사용하지 않는다. 담당자 연락은 별도 승인 후 진행한다.

도구/계정 준비 시간, 문서 읽기, 최초 다운로드·빌드, 장애 해결, 실제 온보딩
시간을 구분해 기록하되, 시작부터 실제 첫 수신까지의 전체 경과도 남긴다.
30분을 넘긴 부분을 빼서 합격 처리하지 않는다. 조건이 충족되지 않아 시작하지
못했다면 `BLOCKED`로 기록한다.

## 참가자가 문서만으로 수행할 흐름

1. 저장소 설치 → DB 비밀번호 입력/생성·다운로드 → 서비스 준비 확인.
2. 관리자 생성 → 첫 로그인 → OTP 설정 또는 건너뛰기 → 대시보드 진입.
3. 앱 연결 온보딩: SDK Key 확인 → APNs/FCM 등록 → SDK 첫 이벤트 확인.
4. 고객 ID로 발송 가능한 기기 한 대 선택 → 테스트 발송 → 기기 수신·탭 확인.
   접수 응답, 공급자 발송, 실제 수신/열기는 구분한다. 같은 `message_id`로
   발송 로그와 이벤트를 대사한다.

중간에 도움을 받았다면 시각·막힌 문장/화면·도움 내용을 기록한다. 참가자의
화면과 요청 ID를 증거로 남기되 비밀번호 다운로드 파일, 키, 세션 쿠키,
푸시 토큰은 결과지에 첨부하지 않는다.

## 참가자별 기록 (복사해서 사용)

| 필드 | 기록 |
|---|---|
| 익명 참가자 ID | P-01 / P-02 / P-03 |
| 시험 일시 / 시간대 | YYYY-MM-DD HH:mm KST |
| 서버·SDK 버전 / OS·도구 버전 | 미기록 |
| 시작·완료 시각 / 전체 경과 | 미기록 |
| 도구/계정 준비·다운로드·빌드 시간 | 미기록 |
| 설치·관리자 로그인·OTP 선택 결과 | 미기록 |
| 첫 이벤트가 서버에 보인 시각 | 미기록 |
| 첫 푸시 접수·기기 수신·탭 시각 | 미기록 |
| test_run_id / message_id / 증거 위치 | 미기록 |
| 막힌 단계·문구 / 도움 횟수·내용 | 미기록 |
| 판정 / 이유 / 검토자 | NOT_RUN |

허용 판정은 `NOT_RUN`, `BLOCKED`, `FAIL`, `PASS`다. PASS에는 독립적으로
문서만 따라 완료했다는 기록, 30분 이내 전체 경과, 실제 수신과 대사 증거가
모두 필요하다. 3명의 결과가 모이기 전에는 B-3를 닫지 않는다.

| 참가자 | 상태 | 시간 | 증거 |
|---|---|---|---|
| P-01 | NOT_RUN | — | — |
| P-02 | NOT_RUN | — | — |
| P-03 | NOT_RUN | — | — |
