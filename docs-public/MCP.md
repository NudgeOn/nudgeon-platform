# AI에서 NudgeOn 사용하기 — MCP

NudgeOn의 선택적 원격 MCP 서버를 통해 AI 클라이언트가 연결된 앱의 지표를 분석하고 세그먼트·저니 초안을 저장할 수 있습니다. 콘솔 계정으로 로그인해 **연결마다 앱 하나와 허용할 권한**을 선택합니다. SDK Key나 Server Key를 AI에 전달하지 않습니다.

MCP는 기본적으로 꺼져 있습니다. 원격 HTTP MCP와 OAuth(PKCE)를 지원하는 클라이언트가 필요하며, 클라이언트별 연결 정책과 지원 여부는 별도로 확인해야 합니다. 이 기능의 자동 검증 범위는 HTTP 프로토콜·OAuth·권한·실제 데이터베이스 집계입니다. 특정 외부 AI 서비스의 실제 계정 연결까지 보장하는 것은 아닙니다.

## 할 수 있는 작업

- 앱 정보, 이벤트·속성 이름과 지표 정의 확인
- 이벤트 추이·구매 이벤트 금액·메시지 성과·퍼널·리텐션 분석
- 제한된 고객 운영 상태, 메시지 로그, 수집 오류 집계 조회
- 세그먼트와 저니 조회 및 초안 생성·편집·검증
- 승인된 연결에서 고객 프로필 검색·조회

발송·활성화·삭제·API 키·공급자 자격 증명 관리는 MCP 도구에 없습니다. AI가 만든 세그먼트는 콘솔에서 운영 세그먼트로 승격해야 하며, 저니는 콘솔 검토 후 활성화합니다. 임의 SQL, 원본 이벤트 전체 반출, 인과적 매출 기여도, A/B 승자 판정도 제공하지 않습니다.

## 연결과 권한

1. 콘솔의 **설정 → MCP**에서 서버 활성화 상태와 연결 주소를 확인합니다.
2. AI 클라이언트에 표시된 `https://api.example.com/mcp` 주소를 추가합니다.
3. NudgeOn 로그인·2단계 인증을 완료합니다.
4. 동의 화면의 클라이언트 ID와 콜백 주소를 확인하고 앱과 권한을 선택합니다. 클라이언트 이름은 연결 앱이 직접 입력한 값이며 NudgeOn이 검증한 브랜드가 아닙니다.
5. 연결 후 AI에게 앱 정보와 지표 카탈로그부터 읽도록 요청합니다.

| 권한 | 가능한 역할 | 범위 |
| --- | --- | --- |
| `mcp:read` | Viewer 이상 | 분석, 운영 상태, 저장된 세그먼트·저니 및 초안 조회 |
| `mcp:drafts:write` | Editor 이상 | 세그먼트·저니 초안 생성·수정 |
| `mcp:customers:read` | Viewer 이상 + 연결별 관리자 승인 + 본인 동의 | 고객 식별자·이메일 검색, 표준·커스텀 프로필 조회 |

현재 콘솔의 조직 역할을 그대로 사용합니다. 관리자는 조직 연결을 관리하고, 일반 멤버는 자신의 연결을 확인·해제할 수 있습니다. 역할 변경, 계정 비활성화, 연결 해제, 고객 접근 승인 철회는 이후 요청부터 반영됩니다. 조직이 2단계 인증을 요구하면 이를 설정하지 않은 멤버의 연결은 사용할 수 없습니다.

고객 프로필 접근은 일반 멤버가 먼저 읽기 연결을 만든 뒤 관리자에게 해당 연결의 승인을 받고, **같은 클라이언트 등록·앱으로 다시 인증하여 고객 조회에 동의**해야 합니다. 관리자는 자신의 연결에 명시적으로 동의할 때 승인할 수 있습니다. 관리자 승인만으로 기존 토큰에 고객 조회 권한이 추가되지는 않습니다. 여러 앱을 쓰려면 앱마다 연결을 만드세요.

기본 고객 조회는 내부 고객 참조, 상태·구독·디바이스 권한 정보만 반환합니다. 다만 읽기 권한으로 공유되는 **세그먼트 조건, 저니 이름·메시지 본문 등 사용자 작성 내용에는 개인정보가 포함될 수 있습니다.** 분석 차원은 허용된 이벤트·국가·언어·채널 등으로 제한되며 임의 프로필 값으로 그룹화하지 않습니다.

## 분석 결과 읽기

분석을 시작할 때 `get_app_context`, `get_metric_catalog`를 호출합니다. 결과의 기간, 시간대, 정의, 분모, 기준 시각, 데이터 품질 정보를 함께 해석해야 합니다.

| 항목 | 집계 기준 |
| --- | --- |
| 기간 | 앱의 IANA 시간대. 시작일 포함·종료일 제외. 기본 완료된 30일, 최대 90일 |
| 이벤트 시간 | 기본 `client_ts`, 명시적으로 `server_ts` 선택 가능 |
| 이벤트·고객 수 | 앱별 `insert_id` 중복 제거 및 사용자 병합 매핑 반영 |
| 비교 | 직전 동일 길이 기간. 기준값 0이면 상대 변화율은 `null` |
| 구매 금액 | `purchase_completed.total_amount`의 유효 숫자를 ISO 통화별 합산. 환불·정산·기여도 미반영 |
| 메시지 | 최초 발송 시각으로 코호트를 정하고 발송 이후 조회 시점까지 관측된 SDK·공급자 결과를 메시지별 중복 제거 |
| 퍼널 | 서로 다른 이벤트 2~5개, 엄격한 시간 순서. 첫 진입부터 기본 7일, 최대 30일 전환 창 |
| 리텐션 | 해당 진입 기간의 첫 코호트 이벤트 후 정확한 로컬 달력 D1·D7·D30 복귀. 생애 최초 가입과는 다름 |

퍼널·리텐션 진입 기간은 최대 30일입니다. 같은 밀리초의 퍼널 이벤트는 순서를 확정하지 않고 모호성 수를 반환합니다. 리텐션 관찰 날짜가 아직 끝나지 않았으면 0이 아니라 `null`입니다. 비율은 `1 = 100%`이며 분모가 0이면 `null`입니다.

전달·열람 데이터가 없다고 실패 또는 열람률 0으로 단정하지 마세요. 채널별 추적 기능과 SDK 구현에 따라 관측 범위가 달라 `coverage_unknown`을 반환할 수 있습니다. 이벤트·사용자 병합·현재 프로필 미러는 비동기 반영됩니다. 국가·언어 차원은 이벤트 당시가 아닌 현재 미러 프로필 기준입니다. 표준 이벤트도 SDK에서 호출해야 수집됩니다.

응답은 최대 500개 집계 행으로 제한됩니다. 초과 시 요청이 거절되므로 기간이나 필터를 좁히세요. 통계 분석용 ClickHouse 쿼리는 최대 30초·256MiB이며 연결별 분석 동시 실행과 요청 빈도도 제한합니다. 결과는 관측치이고 원인·통계적 유의성·광고 기여도를 증명하지 않습니다.

예시 요청:

> 지난 30일 sign_up → login → purchase_completed 퍼널을 7일 전환 창으로 분석해 줘. 각 단계 고객 수와 전환율, 같은 시각의 이벤트로 확정할 수 없는 부분도 알려 줘.

> 최근 완료된 30일의 메시지 성과를 직전 기간과 비교해 줘. 지표 정의와 분모, 채널별 추적 범위를 함께 설명해 줘.

> KR 고객 조건의 세그먼트 초안과 sign_up 환영 저니 초안을 만들어 줘. 검증 결과와 콘솔 검토 링크를 알려 줘.

## 초안과 동시 편집

생성 도구의 `request_id`는 생성 작업마다 만든 UUID입니다. 같은 요청을 재시도할 때 같은 UUID와 같은 내용을 사용하면 초안이 중복 생성되지 않습니다. 같은 UUID에 다른 내용을 보내면 충돌합니다.

수정할 때는 최신 초안을 읽고 응답의 `revision`을 `expected_revision`으로 보냅니다. `REVISION_CONFLICT`이면 다시 읽고 변경 내용을 비교한 후 재시도합니다. 콘솔과 AI가 동시에 편집해도 이전 내용을 덮어쓰지 않습니다.

- 세그먼트 초안은 운영 평가·발송에 사용되지 않습니다. 미리보기는 예상 수만 반환합니다. 콘솔에서 검토한 버전을 승격하면 새 운영 세그먼트가 한 번 생성되고 원래 초안은 잠깁니다.
- MCP는 한 번도 게시하지 않은 `draft` 저니만 수정할 수 있습니다. 활성·일시정지·과거 게시 저니는 새 초안으로 복사합니다.
- 저니 저장은 검증 문제와 콘솔 링크를 반환합니다. `validate_journey_draft`로 다시 검증하고, 콘솔에서 최종 확인합니다. 검증 성공이 자동 발송을 의미하지는 않습니다.
- `nudgeon://segment-schema`, `nudgeon://journey-schema`, `nudgeon://draft-guide` 리소스를 참고합니다. 저니 그래프 v2 사용 가능 여부는 `list_journeys`의 `capabilities`를 확인합니다.

## 운영 설정

먼저 PostgreSQL 마이그레이션 `0013_mcp_oauth.sql`, `0014_mcp_segment_drafts.sql`을 포함한 현재 마이그레이터를 실행합니다. 기존 데이터를 삭제하지 않는 추가형 변경입니다. 그런 다음 API 환경변수를 설정합니다.

```dotenv
MCP_ENABLED=true
MCP_PUBLIC_URL=https://api.example.com
MCP_CONSOLE_URL=https://console.example.com
```

두 URL은 경로·쿼리 없는 **공개 origin**이어야 합니다. `/mcp`, `/api`를 붙이지 않습니다. 운영은 HTTPS가 필요하며 개발용 loopback HTTP만 예외입니다. `MCP_CONSOLE_URL`은 콘솔 CORS 설정과 일치시킵니다. 기본 Compose는 `deploy/.env`, Safe Boot는 실행 환경이나 `.nudgeon/compose.env`에 값을 추가하고 API·게이트웨이를 재기동합니다. Safe Boot의 공개 origin이 API와 콘솔에 공통이면 두 URL도 동일하게 설정합니다.

리버스 프록시는 다음 경로를 API로 전달하고 원래 `Host`(포트 포함)를 유지해야 합니다. `/mcp/authorize`는 콘솔 화면이므로 별도 경로입니다. 저장소의 Safe Boot 게이트웨이는 이 구분을 포함합니다.

- `/mcp` — Streamable HTTP MCP
- `/.well-known/oauth-authorization-server`
- `/.well-known/oauth-protected-resource/mcp` 및 `/.well-known/oauth-protected-resource`
- `/oauth/register`, `/oauth/authorize`, `/oauth/token`, `/oauth/revoke`

OAuth는 공개 클라이언트 동적 등록, 정확히 일치하는 콜백 URI, PKCE S256, `resource=<MCP_PUBLIC_URL>/mcp`를 사용합니다. 액세스 토큰은 15분, 회전형 리프레시 토큰은 30일입니다. 원문 토큰 대신 해시를 저장하며 사용된 리프레시 토큰을 재사용하면 연결을 해제합니다. 토큰은 헤더로만 보내고 URL·로그에 넣지 않습니다. 외부 클라이언트가 자체 HTTPS 콜백 또는 로컬 loopback 콜백을 사용하는지 확인하세요.

MCP 연결·승인·해제·도구 실행·초안 쓰기는 감사 로그에 남깁니다. 도구 감사에는 식별자·결과·시간을 기록하며 입력 본문·원문 프로필·토큰을 기록하지 않습니다. `MCP_ENABLED=false`로 되돌리면 MCP와 OAuth 엔드포인트가 차단됩니다. 이미 발급한 연결도 영구 폐기하려면 비활성화 전에 콘솔에서 해제하세요.

Management API 계약은 [API 가이드](API.md), 배포 절차는 [배포 가이드](DEPLOY.md), 경로 스펙은 [`mcp.openapi.json`](../packages/openapi/mcp.openapi.json)·[`mcp-analytics.openapi.json`](../packages/openapi/mcp-analytics.openapi.json)·[`mcp-oauth.openapi.json`](../packages/openapi/mcp-oauth.openapi.json)에 있습니다.
