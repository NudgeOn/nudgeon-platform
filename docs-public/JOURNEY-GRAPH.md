# 저니 그래프 v2

푸시 메시지·고정 대기에 조건 분기, 이벤트 대기, A/B 분기를 추가합니다. 각 고객은 진입한 불변 버전에서
하나의 경로를 실행합니다. 합류는 다른 고객이나 경로를 기다리지 않으며, 반복 연결·동시 분기는 지원하지 않습니다.

## 단계별 동작

| 단계 | 출력 | 기준 |
| --- | --- | --- |
| 푸시 메시지 | `next` | 기존 수신 동의·조용시간·빈도 정책 적용 |
| 고정 대기 | `next` | 설정한 시간이 지난 후 진행 |
| 조건 분기 | `true`, `false` | 도착 시점의 고객 속성·기준 시각을 저장한 뒤 평가 |
| 이벤트 대기 | `matched`, `timeout` | 등록 후 처음 접수한 이벤트 또는 제한시간 |
| A/B 분기 | 영구 경로 ID | 2~4개, 각 1% 이상 정수, 합계 100% |

조건은 Segment DSL v1의 속성 비교, 이벤트 수행·미수행, AND/OR 그룹을 사용합니다. 이벤트 조회는 기본 30일,
최대 180일입니다. 횟수·이벤트 속성 필터는 지원하지 않습니다. 날짜는 `YYYY-MM-DD` 또는 시간대가 있는
ISO 시각을 받습니다. 속성·기준 시각과 확정 결과를 저장하므로 재시도 때 기준이 바뀌지 않습니다.
ClickHouse 조회 실패나 아직 반영되지 않은 관련 이벤트는 `false`가 되지 않으며, 제한된 재시도 후 실패 사유를 기록합니다.

이벤트 제한시간은 필수이며 기본 24시간입니다. `/v1/track`이 성공(202)하기 전에 PostgreSQL inbox와 outbox를
같은 트랜잭션으로 저장합니다. 저장 실패는 503이며 같은 `insert_id`로 재시도할 수 있습니다. 중복 이벤트는
최초 접수 시각·고객별 순서를 유지합니다. 성공은 영속 접수 완료를 뜻하며, 분석 저장소 반영이나 푸시 완료를 뜻하지 않습니다.

- 기기 시각 대신 서버 최초 접수 시각과 고객별 접수 순서를 사용합니다. 오프라인 행동도 대기 등록 후 처음 접수되면 대상입니다.
- 대기 등록 전에 접수된 이벤트는 재전송해도 제외합니다. 같은 이벤트로 연속된 대기 두 개를 통과하지 않습니다.
- `received_at < deadline`만 인정합니다. 기한과 같거나 이후면 시간 초과이며, 기한 전 접수된 이벤트는 워커 처리가 늦어도 인정합니다.
- 등록·판정·시간 초과는 같은 고객 cursor와 실행 상태 잠금을 사용합니다. 경로 결정·상태 이동·발송 outbox는 트랜잭션으로 함께 저장합니다.
- 일시정지 중에도 기한은 흐릅니다. 이벤트 결과는 보존하고 경로 이동은 재개 후 처리합니다. 전환 종료와 같은 이벤트라면 종료가 우선입니다.

고객 식별자를 병합할 때 기존 익명 고객의 v2 진행 실행은 `identity_merged` 사유로 종료합니다. 서로 다른 접수 순서를
섞거나 구매 이벤트를 잘못 시간 초과로 처리하지 않기 위한 정책입니다. 병합 대상인 로그인 고객의 진행 실행,
과거 결과와 v1 실행은 유지합니다. 익명 프로필에 처음 외부 ID를 붙이는 경우처럼 같은 내부 고객 ID가 유지되면 실행도 유지합니다.
두 프로필 사이에서 진행 실행을 옮기는 기능은 지원하지 않습니다.

A/B는 SHA-256 기반으로 저니 ID·노드 ID·고객 ID에서 고정 배정합니다. 실행 버전·재진입 횟수는 배정값에 포함하지 않습니다.
첫 활성화 뒤 경로 ID·순서·비율은 고정되며 이름만 바꿀 수 있습니다. **새 실험으로 시작**은 노드 ID를 새로 만들고,
진행 중인 고객은 기존 버전의 실험을 계속합니다. 고객 수가 적으면 실제 인원 비율은 설정 비율과 다를 수 있습니다.
기간을 정한 재진입은 1~106751일을 지원합니다.

## 정의와 호환성

기존 URL과 `{name, definition}` 요청 형태는 유지합니다. v2는 다음 정보를 명시합니다.

```json
{
  "schema_version": 2,
  "entry": { "type": "trigger", "trigger_event": "product_viewed" },
  "start_node_id": "offer",
  "nodes": [{ "id": "offer", "type": "message", "push": { "title": "안녕하세요", "body": "혜택을 확인해 보세요" } }],
  "edges": [{ "id": "offer-end", "source": "offer", "source_port": "next", "target": null }],
  "exit": {},
  "settings": { "category": "marketing", "reentry": "never" }
}
```

노드·연결·경로 ID는 UTF-8 최대 128바이트입니다. 각 출력은 연결 하나를 가져야 하고 `target: null`은 종료입니다.
활성화 전 순환, 도달 불가능한 노드, 출력 누락, 조건·시간·비율을 검사합니다. 오류에는 노드·연결·입력 위치가 포함됩니다.
저장 응답의 `revision`과 검증 응답의 `revision`이 같아야 하며, `/activate`에 검증한 값을 넘깁니다.
저니 행 잠금 안에서 이를 확인하고 버전을 생성하므로 다른 편집 내용이 끼어들면 409를 반환합니다.

v1 활성 버전을 다시 쓰거나 진행 고객을 v2로 옮기지 않습니다. 편집기에서만 v1을 그래프로 표시하고, 수정한 초안을
저장할 때 v2로 전환합니다. v1은 기존 배열 순서·발송 멱등 키를 유지합니다. v2는 실행 ID까지 포함한 발송 키로
같은 진입 이벤트 재전달은 제외하면서 허용된 새로운 재진입은 발송할 수 있습니다. 디바이스 ID는 두 방식 모두 포함합니다.

## 편집과 리포트

5종 팔레트, 경로별 `+`, 노드별 설정 패널, 경로 합류, 분기 삭제 미리보기와 되돌리기를 제공합니다. 새 분기를 넣으면
각 출력에서 기존 다음 단계 연결을 보존합니다. 삭제 때는 보존할 경로를 고르고, 다른 경로에서도 도달하는 공통 노드는 유지합니다.
React Flow와 Dagre로 배치하며 구조 변경·정렬 요청에만 배치를 갱신합니다. 문구를 입력하는 동안 화면은 이동하지 않습니다.
표시 대기시간은 모든 노드의 합이 아니라 경로별 설정 대기 범위입니다. 야간 정책·실행 지연은 이 범위에 포함하지 않습니다.

리포트는 실행 버전을 선택하여 해당 불변 정의와 집계를 함께 표시합니다. 조건 통과, 이벤트 대기·발생·시간 초과,
A/B 경로별 실행 수와 고유 고객 수를 구분합니다. 재진입은 실행 수에 다시 포함하고 고유 고객은 경로별 중복 제거합니다.
과거 미계측 버전은 **집계 없음**을 표시합니다. 발송 접수는 전송 서비스가 받아들인 건수로, 실제 도달·열람이나 고객 수가 아닙니다.

## 검증

단위 테스트는 외부 저장소 없이 실행할 수 있습니다.

```bash
pnpm --filter @onda/journey-model test
pnpm --filter @onda/console test
pnpm --filter @onda/api test
go test ./apps/worker/... ./packages/libqueue-go/...
./scripts/lint-rules.sh
```

통합 테스트에는 **테스트 전용** PostgreSQL·Redis·ClickHouse를 준비하고 현재 스키마를 먼저 적용합니다.
아래 환경 변수는 운영 저장소를 가리키면 안 됩니다. PostgreSQL은 테스트용 스키마 또는 고유 테넌트를 만들고 정리합니다.
ClickHouse는 테스트용 고유 테넌트 데이터가 남을 수 있으므로 별도 인스턴스를 사용하세요.

| 환경 변수 | 사용처 |
| --- | --- |
| `ONDA_JOURNEY_TEST_DATABASE_URL` | API·워커 저니 PostgreSQL 테스트 |
| `ONDA_JOURNEY_TEST_CLICKHOUSE_URL` | API는 HTTP URL, Go는 ClickHouse 드라이버 DSN |
| `ONDA_JOURNEY_TEST_REDIS_URL` | 실제 워커 E2E 전용 Redis DB |
| `ONDA_RECEIPT_TEST_DATABASE_URL` | API·ingest 수집/삭제 회귀 |
| `ONDA_RECEIPT_TEST_CLICKHOUSE_DSN` | Go ingest의 실제 ClickHouse 반영 |
| `ONDA_MIGRATE_TEST_DATABASE_URL` | 기존 v1 스키마와 데이터의 반복 업그레이드 |

```bash
pnpm --filter @onda/api exec vitest run src/journeys/journeys.integration.test.ts src/ingestion/event-receipts.test.ts
go test -race ./apps/worker/internal/journey ./apps/worker/internal/trigger ./apps/worker/internal/ingest
go test ./apps/worker/cmd/migrate
```

워커 E2E는 실제 Redis 큐와 수집·트리거·저니·채널 워커를 연결합니다. 채널 플러그인만 테스트 전송기로 대체하므로
실제 APNs/FCM이나 고객에게 푸시를 보내지 않습니다. 중복 outbox 재전달 후에도 전송 호출이 한 번인지 확인합니다.
프로덕션 APNs/FCM 도달, 실제 고객 이벤트 연동, 대규모 부하 성능은 이 검증의 범위가 아닙니다.

배포 순서와 되돌리기 제한은 [배포 가이드](./DEPLOY.md#저니-그래프-v2-공개-순서)를 따릅니다.
